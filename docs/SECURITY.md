# 安全说明

## 首先阅读：演示认证禁止用于生产

项目为了把注意力集中在审批流和 Spring 教学点上，直接从以下请求头构造当前用户：

```text
X-User-Id: applicant01
X-User-Name: applicant01
X-Role: APPLICANT
X-Dept-Id: D001
```

这些值由调用者提供，**没有密码校验、签名校验、令牌校验或防重放能力**。任何人都可以把自己写成管理员或审批员。它不是“简化但基本安全”的登录，而是完全不可信的教学桩。

生产环境必须删除/禁用这套 Header 认证，使用组织统一身份平台和经过验证的 Spring Security 方案。边界网关还应移除来自公网的所有同名头，防止它们覆盖网关注入的可信身份。

## 演示密钥

开发配置中的默认 AES 密钥仅便于开箱运行，视为已经公开。正式环境应：

- 从 KMS/HSM/Vault 获取密钥或数据密钥，不把密钥提交到 Git、镜像或普通配置中心；
- 使用至少 256 bit 随机主密钥，并记录密钥版本而非密钥本身；
- 为每次加密生成唯一的 96 bit GCM IV，绝不在相同密钥下复用 IV；
- 对加密失败采用 fail-closed，不能降级为明文入库；
- 设计可暂停、可审计、可回滚验证的在线密钥轮换任务；
- 把盲索引、数据加密和令牌签名分别使用不同密钥。

本地可通过 `BANK_CRYPTO_KEY` 设置 Base64 密钥。改变密钥会使旧密文无法解密，本例未实现版本/轮换；不要把真实数据输入此教学项目。`prod` 关闭演示认证且不加载该过滤器，安全闸禁止关闭加密；本例未实现生产 IAM 接入，关闭演示认证后请求会被拒绝。

## 日志与错误处理

以下内容禁止出现在业务日志、访问日志、审计详情、APM 标签或异常消息中：

- 手机号、身份证号、完整账户号及其原始请求体；
- AES 密钥、IV、完整密文和认证标签；
- 认证令牌、Cookie、密码、验证码；
- 完整 SQL 参数或解密后的领域对象 `toString()`。

异常响应应返回稳定错误码和 trace id，不应把数据库错误、SQL、包名栈或加密细节暴露给前端。审计内容应描述“谁在何时对哪笔业务做了什么及结果”，敏感值只保留必要的脱敏片段。

## 数据权限原则

- 申请人：创建草稿、提交、查看本人记录；通过 resubmit 修改被驳回申请并重提（无草稿编辑接口）。
- 一级审批员：只处理本部门 `PENDING_L1`，且不能审批自己的申请。
- 二至四级审批员：同样只看本部门记录，只处理对应级别待办；没有 ALL 通配部门。
- 审计员：只读业务与审计记录，默认看脱敏值。
- 管理员：管理能力不等于无限制查看敏感明文；生产应拆分平台管理员和数据解密权限。

Service 公开方法上的 `@PreAuthorize` 是第一层，列表查询 applicant/department 条件与详情/命令的所有权检查是第二层。审批链再次校验状态、级别、部门、职责分离。不能先查出所有数据再仅靠前端隐藏。

## 审计与不可抵赖边界

示例 `audit_log` 与业务表在同一个数据库和事务中，可以演示原子性，但数据库管理员仍可修改两者，因此不具备强不可抵赖性。生产环境应把审计事件异步复制到独立权限域的不可变存储；可采用哈希链/签名和可信时间戳增强篡改检测，并定期验证链完整性。

本例审计仅记录成功的创建、提交、审批、驳回与重提；不覆盖失败鉴权、登录或每次读取。用途/审批意见是自由文本，未实现个人信息自动识别，输入中不得夹带敏感明文。GCM 能检测未经授权的密文修改，但本例未使用 AAD 绑定行和列，无法识别数据库内合法密文被复制或交换；生产应结合租户、业务主键、字段名与密钥版本设计 AAD，并配套数据完整性校验。

## 上线前最低检查

- [ ] 演示 Header 身份过滤器在生产 profile 无法加载。
- [ ] 没有开发默认密钥、数据库口令或调试端点。
- [ ] 敏感值加密、脱敏、授权、审计均有自动化负向测试。
- [ ] 所有越权场景返回 403/404，不泄露记录是否存在。
- [ ] 并发审批和重复请求有条件更新或幂等保护。

- [ ] 依赖、容器镜像和许可证扫描通过。
- [ ] 数据留存、删除、备份、恢复和密钥销毁策略已评审。
- [ ] 银行信息安全、法务合规和业务风控完成正式验收。
